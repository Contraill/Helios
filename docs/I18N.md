# Language and Localisation

## Supported locales

Helios supports two complete interface locales:

- `en` — English;
- `tr` — Turkish.

Visible copy, accessible names, validation messages, loading/empty/error states, date/number formatting and route metadata all use the same typed locale contract. Scientific values and source identities remain unchanged; only their presentation and explanatory copy are localised.

## URL and rendering contract

Each locale has its own URL space. English keeps the unprefixed URLs; Turkish lives under `/tr`:

| Page    | English      | Turkish         |
| ------- | ------------ | --------------- |
| Home    | `/`          | `/tr`           |
| Explore | `/explore`   | `/tr/explore`   |
| Mars    | `/body/mars` | `/tr/body/mars` |

All pages live under `src/app/[locale]/` and are prerendered for both locales (`generateStaticParams` in the locale layout). `src/proxy.ts` maps requests onto that segment:

- an unprefixed URL is rewritten to `/en/...` internally, so the browser URL stays `/explore`;
- `/en/...` is served but canonicalises to the unprefixed URL (a redirect would loop on internal rewrites);
- `/tr/...` is served as is;
- unmatched paths reach `[locale]/[...rest]` and render the localised 404 inside the site shell.

Pages read the locale from the route param through `getRequestLocale(params)`; `loading.tsx` and `not-found.tsx`, which receive no params, read it from the client locale store that the layout seeds.

Internal links use `@/components/localized-link`, a drop-in for `next/link` that adds the active locale prefix. Hash-only and external links are left unchanged.

## Preference

The language switcher stores the choice in the `helios-locale` cookie for one year and replaces the current URL with its counterpart in the other locale, keeping the query string and hash. When a visitor with a saved Turkish preference opens an unprefixed URL, the proxy redirects them to the `/tr` version. Crawlers carry no cookie, so they always see the URL they requested.

A language change:

- keeps the current page, query and hash;
- keeps Explore selection and simulation state, which live in module-level stores;
- updates `<html lang>` to `en-US` or `tr-TR`;
- never changes data freshness, source values or calculations.

English is the deterministic fallback for an unknown locale param.

## Indexing

- Every page publishes a self-referencing canonical in its own language (`/body/mars` or `/tr/body/mars`).
- Every page publishes `hreflang` alternates for `en`, `tr` and `x-default` (English).
- The sitemap lists every page once per locale (136 entries), each with the same alternates.
- Legacy `/planet` and `/object` routes canonicalise to `/body` in the matching locale.
- Social images remain bilingual and language-neutral; titles and descriptions follow the page locale.

## Translation coverage

The EN/TR contract covers:

- global navigation, footer, skip link and error pages;
- home, Explore, Compare, Missions, Data, About and Case Study;
- all Explore docks, summaries, loading and WebGL fallback states;
- 57 body pages, four region pages and eight custom planet compositions;
- remote-data current, stale, fallback, partial, empty and unavailable states;
- metadata, accessible labels, forms, source/provenance labels and locale formatting.

## Translation rules

- Data definitions and uncertainty qualifiers must survive translation.
- `historical`, `latest-available`, `near-live`, `reference` and schematic representation remain distinct.
- A provider or mission proper name is not translated unless the official source uses a localised form.
- Units are formatted at presentation time; source values are not duplicated into locale-specific datasets.
- Missing copy is a release error. English is used only as the fallback for an unknown locale, not as a silent per-field fallback.

## Verification

```bash
pnpm audit:i18n
pnpm audit:editorial
```

The language audit compares catalogue shape, checks required server routes, rejects retired English-only Explore copy and verifies the locale URL contract (proxy, switcher and cookie preference). The editorial audit server-renders both locales across the complete semantic library.
